What this stop sets up

Three files, one job: make the project reproducible

Before any RAG logic runs, a Python project needs a place to keep configuration and dependencies — otherwise every module ends up hardcoding its own copy of a path or a model name, and two files quietly drift out of agreement. This stop creates three files that solve exactly that, once, so nothing later has to think about it again.

config.py

The single source of truth for paths, model names, and tunable numbers. Every other file imports from here instead of keeping its own copy.

requirements.txt

Pins the exact library versions this project needs, so pip install -r requirements.txt rebuilds the same environment on any machine.

.gitignore

Tells git which files to never track: regenerable outputs like the vector index, so it doesn't end up committed and bloating the repo.

No secrets to manage

Everything in this pipeline — the embedding model and the LLM — runs on your own machine. No API key, no .env file, no risk of accidentally committing a secret. One less thing to get wrong.

Concept

Config first, logic second

config.py centralizes two kinds of decisions that would otherwise get scattered across files:

  • Paths — where the PDF lives, where the vector index gets cached.
  • Model choices — which embedding model, which local LLM, and which host it's served from.

Every later stop imports from it rather than repeating these decisions. Settings are still read through os.getenv("NAME", default) even though nothing here is secret — that pattern isn't just for hiding values, it's also the simplest way to let someone override a default (say, a smaller local model on a laptop with less memory) without editing the file at all.

# --- Paths ---
BASE_DIR = Path(__file__).resolve().parent
DATA_DIR = BASE_DIR / "data"
VECTORSTORE_DIR = BASE_DIR / "vectorstore"
DEFAULT_PDF_PATH = DATA_DIR / "your-document.pdf"

# --- Embeddings ---
EMBEDDING_MODEL_NAME = os.getenv(
    "EMBEDDING_MODEL_NAME", "sentence-transformers/all-MiniLM-L6-v2"
)

# --- LLM (runs locally, no API key) ---
OLLAMA_MODEL_NAME = os.getenv("OLLAMA_MODEL_NAME", "qwen3")
OLLAMA_BASE_URL = os.getenv("OLLAMA_BASE_URL", "http://localhost:11434")
LLM_TEMPERATURE = float(os.getenv("LLM_TEMPERATURE", "0"))

# --- Retrieval ---
RETRIEVAL_K = int(os.getenv("RETRIEVAL_K", "4"))

Imports are trimmed from this snippet — this is just the part of config.py this stop cares about. A couple more settings (chunk size and overlap) get added once Stop 2 needs them.

Every constant is typed at the point it's read (int(...), float(...), Path) — environment variables are always strings, so the conversion has to happen somewhere, and doing it once here means nothing downstream has to think about it.

Notice there's no import of anything for reading a .env file, and nothing named *_API_KEY. That's not an oversight — it falls out directly from every model in this pipeline running locally.

Quiz

Check yourself

1. Why keep configuration like paths and model names in one central file instead of letting each module hardcode its own?

Centralizing config means a single edit propagates everywhere it's used — no risk of two files quietly disagreeing on a model name or path.

2. This project has no API key and no .env file. Why does config.py still read settings through os.getenv("NAME", default) instead of just hardcoding them?

Environment variables aren't just for secrets — they're a general mechanism for overriding a default without touching source code, which is exactly how this project lets you swap in a different local model size.

3. Why is a locally-built vector index excluded from version control while the source PDF isn't?

Anything that can be rebuilt from source doesn't need to live in version control — committing it just adds bloat and a second copy that can drift out of sync.
