What "RAG" actually means

A chat model is trained once, on a fixed pile of text, and then frozen. Ask it about a PDF sitting on your laptop — a paper, a contract, a manual — and it has never seen that specific document. It also can't just read the whole thing before every reply: documents are long, and stuffing an entire PDF into every question is slow and, past a certain length, doesn't even fit.

Retrieval-Augmented Generation solves this with one trick: instead of asking the model to answer from memory, first find the handful of paragraphs that are actually relevant to this question, and only show the model those. The name describes the trick literally:

RetrievalSearch the document for the small number of chunks most relevant to the question being asked.
AugmentedAdd those chunks into the prompt, alongside the question, before sending anything to the model.
GenerationThe model writes an answer using the chunks it was handed — not from memory.

Think closed-book exam versus open-book. A model with no retrieval answers from memory — it either knows the fact or it doesn't, and sometimes it guesses and is wrong with total confidence. A RAG pipeline hands it the exact right page first, open to the right paragraph, then asks the question. The model still does the reasoning; it's just reasoning over real text instead of a half-remembered guess.

In practice, that means every question makes two trips: a retrieval trip, which searches the document for the closest-matching pieces, and a generation trip, which hands those pieces to a chat model and asks it to answer using only what it was given. Everything below — 11 stations, 5 stops — is that two-trip process broken open and drawn as a line you can walk stop by stop.

What we need to build RAG

Core Components

ComponentWhat it doesCovered in
Document loadersRead a source document into a standard format the rest of the pipeline can work with.Stop 2
Text splittersBreak a loaded document into small, focused chunks sized to fit an embedding model.Stop 2
EmbeddingsTurn each chunk into a vector — numbers positioned so similar meaning sits close together.Stop 3
Vector storesStore those vectors and search them for the ones closest to a given question.Stop 3
RetrieversWrap a vector store's search behind a standard interface: question in, top-k chunks out.Stop 4
LLMsRead the retrieved chunks plus the question, and generate an answer grounded in what it was given.Stop 4
EvaluationMeasure whether retrieval found the right chunks and whether the answer is actually correct.Not built in this project — a natural next step

This project builds all seven pieces with LangChain — a framework that ships pre-built, standard implementations of each one (loaders, splitters, embedding wrappers, vector store wrappers, retrievers, chat model clients), so you're wiring components together instead of writing PDF parsing or prompt-stuffing from scratch. It's one way to build RAG, not the only way — Stop 2 covers that trade-off in more depth, including what you'd give up by skipping a framework entirely.
