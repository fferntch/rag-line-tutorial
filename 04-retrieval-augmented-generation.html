Concept

Grounding, not guessing

Retrieval only gets you the raw material — an LLM still has to turn "chunks + question" into an actual answer. Left alone, an LLM will happily answer from its training data instead of the document in front of it, which defeats the entire point of building a RAG pipeline. This stop's job is to make sure that never happens, in three steps.

1

Retrieve the top matches

The FAISS index from Stop 3 becomes a retriever: given a question, it returns the handful of chunks whose meaning is closest to it — 4 of them, by default, in this project.

from langchain_core.prompts import ChatPromptTemplate

SYSTEM_PROMPT = (
    "You are a research assistant answering questions about a technical "
    "document. Use only the retrieved context below to answer the "
    "question. If the answer is not contained in the context, say you "
    "don't know instead of guessing.\n\n"
    "Context:\n{context}"
)

QA_PROMPT = ChatPromptTemplate.from_messages(
    [
        ("system", SYSTEM_PROMPT),
        ("human", "{input}"),
    ]
)

rag.py (part 2)Python
def get_llm() -> ChatOllama:
    """Configure the local chat model used to generate answers."""
    return ChatOllama(
        model=config.OLLAMA_MODEL_NAME,
        base_url=config.OLLAMA_BASE_URL,
        temperature=config.LLM_TEMPERATURE,
    )


def build_rag_chain(vectorstore: FAISS) -> Runnable:
    """Wire retriever + prompt + LLM into a single LCEL retrieval chain."""
    retriever = vectorstore.as_retriever(search_kwargs={"k": config.RETRIEVAL_K})
    llm = get_llm()
    combine_docs_chain = create_stuff_documents_chain(llm, QA_PROMPT)
    return create_retrieval_chain(retriever, combine_docs_chain)


def answer_question(chain: Runnable, question: str) -> Tuple[str, List[Document]]:
    """Run a question through the chain and return (answer, source_chunks)."""
    result = chain.invoke({"input": question})
    return result["answer"], result["context"]

get_llm() explicitly sets temperature=0 instead of leaving the model's own default. Many chat models default to a nonzero temperature tuned for varied, conversational output; for factual Q&A grounded in retrieved text, a deterministic, low-temperature setting is what actually reduces hallucination and keeps the same question giving the same answer run to run.

Temperature ranges from 0 (fully deterministic) up to roughly 1–2 depending on the model, increasing randomness/creativity as it climbs. For grounded RAG Q&A, 0–0.3 is the practical range — low enough that the model reports what's actually in the retrieved context instead of improvising. This project uses temperature=0; nudging it to ~0.2 is reasonable if answers ever feel too clipped or repetitive across similar questions.

create_retrieval_chain's result dict uses the key "answer", not "result" — a common trip-up if you've seen the older, now-deprecated RetrievalQA chain, which used a different key.

A separate function, check_ollama_ready(), handles the "is this actually available" question — this code assumes the model is reachable and lets the call fail loudly if it isn't. Stop 5 covers where that check actually runs.

For beginners

Why this chat LLM, and what else fits?

Any chat-capable model can play this role — the RAG pattern above (retrieve, stuff into a prompt, generate) doesn't depend on which one answers. Swapping providers is mostly a one-line change to get_llm() in rag.py, plus whichever LangChain chat class that provider ships. The real decision is a trade-off between running locally (free, private, capped by your own hardware) and calling a hosted API (usually stronger reasoning and instruction-following, at a per-token cost and with your data leaving your machine).

Quiz

Check yourself

1. What should a RAG system's prompt instruct the model to do when the answer isn't in the retrieved context?

This is the whole point of the "grounding" instruction — it stops the model from hallucinating when retrieval comes up empty.

2. Why is it useful for a RAG chain to return the source chunks alongside the generated answer?

Grounding only matters if it's checkable — showing the source chunks is what turns "trust me" into "here's exactly what this came from."

3. Why does get_llm() pass temperature=0 explicitly?

A model's default temperature is usually tuned for varied conversational output; a RAG pipeline wants the model reporting what's in the retrieved context, not improvising around it.
